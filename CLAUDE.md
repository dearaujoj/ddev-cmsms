# ddev-cmsms

DDEV add-on that turns a CMS Made Simple (CMSMS 2.2.x) module/plugin/admin-theme repo into a fully installed, disposable dev site. Installed into a project with `ddev add-on get dearaujoj/ddev-cmsms`; the CMSMS core lives in the project's gitignored `.cmsms/public/` (docroot), the extension is symlinked in and registered.

Design spec and implementation plan live in `docs/superpowers/` — read them before structural changes.

## Commands

```bash
BATS_LIB_PATH=/opt/homebrew/lib bats tests           # full suite (~several min; rebuilds test project)
BATS_LIB_PATH=/opt/homebrew/lib bats tests/test.bats --filter "db stage"   # one test (needs prior bootstrap run)
scripts/update-versions.sh > cmsms/versions.json      # regenerate version→URL map from the CMSMS Forge
```

Tests use a shared long-lived project at `~/tmp/test-ddev-cmsms`; the first test in `test.bats` wipes and rebuilds it. After editing add-on files, refresh the test project with `cd ~/tmp/test-ddev-cmsms && ddev add-on get <this repo's absolute path>` before iterating with `--filter`. bats libraries come from `brew tap kaos/shell` (`bats-assert`, `bats-file`, plus `bats-support`).

## Architecture

- `install.yaml` — add-on manifest: ships both commands, `config.cmsms.yaml`, `docker-compose.cmsms.yaml`, and the `cmsms/` payload dir; depends on `ddev/ddev-phpmyadmin`; post-install appends `.cmsms/` + `.ddev/cmsms/cache/` to the project's .gitignore and pre-creates `cmsms/cache`.
- `commands/web/cmsms-install` — the pipeline, staged `all|fetch|files|db|link`, run by the post-start hook. Idempotency marker: `config.php` exists AND `SELECT version FROM cms_version` succeeds. `all` must ALWAYS exit 0 on an already-installed or unconfigured project (hook safety) — the link refresh on installed starts runs `( stage_link ) || warn` in a subshell precisely because `die()` calls `exit`.
- `cmsms/extract.php` — unpacks the self-extracting installer (`Phar` needs a `.phar` filename, hence the copy) and the core tarball; writes `.extract-complete` marker only after both succeed.
- `cmsms/install.php` — headless DB installer. The official wizard refuses CLI, so this replicates `wizard_step8/9::do_install()` by including the installer's own `app/install/*.php` with a stubbed `__appbase\get_app()`, `ilang`/`status_msg`/`verbose_msg`, and the exact globals (`CMS_INSTALL_PAGE`, `DONT_LOAD_DB`, `DONT_LOAD_SMARTY`, `CMS_PHAR_INSTALLER`). Order matters: sitemask salt must be set BEFORE `base.php` (password hashing reads it).
- `cmsms/register-extension.php`, `cmsms/package.php` — CLI bootstrap of the installed core for `InstallModule` / `CreateXMLPackage`.
- `commands/host/cmsms` — `ddev cmsms setup|admin|status|reinstall|package`. Setup validates name `^[A-Za-z0-9_]+$` (that invariant makes later SQL interpolation safe) and writes `.ddev/config.cmsms-project.yaml` (`CMSMS_EXT_TYPE/NAME`, `CMSMS_VERSION`).
- `cmsms/versions.json` — version→URL map (Forge `/frs/download/<id>` endpoints, 302→S3, so curl must keep `-L`). Regenerated by `scripts/update-versions.sh`.

## Hard-won constraints (violating these re-breaks fixed bugs)

- **Never symlink `modules/<Name>` to the repo root** — the repo contains `.cmsms/public/modules/<Name>`, creating an infinite scan cycle. `link_entries` makes per-entry links with the `CMSMS_LINK_EXCLUDE` list (`.ddev .cmsms .git .gitignore dist docs`).
- `/mnt/ddev_config` is **read-only** in the web container; only `cmsms/cache` is writable, via the scoped rw bind in `docker-compose.cmsms.yaml`.
- Every shipped file needs the literal `#ddev-generated` string (JSON: the `"_comment"` key) or `ddev add-on get` will never update it in user projects.
- `.cmsms/public/uploads` is a Mutagen bind-mount (`upload_dirs`); `rm -rf .cmsms/public` fails "Device or resource busy" — reinstall empties in place, skipping the mountpoint.
- CMSMS bootstrap quirks (2.2.22): `require_once lib/smarty/Smarty.class.php` after `include.php` (headless runs never trigger Smarty's autoloader), and `unset($GLOBALS['CMS_INSTALL_PAGE'])` before `ModuleOperations` calls (else fresh non-system modules are discarded on load).
- Host bash is macOS 3.2 — no bash-4 constructs in `commands/host/cmsms`.
- Don't pin `php_version` in `config.cmsms.yaml`: config.*.yaml merges after config.yaml and would silently override `ddev config --php-version`.

## Conventions

- Conventional commit prefixes (`feat:`/`fix:`/`docs:`/`ci:`/`chore:`).
- README documents implemented reality — when changing a command's behavior or flags, update the README in the same commit (reviews treat doc/code drift as a defect).
- 2.2.22 is the locally verified core; 2.2.21/2.2.19 compatibility rides on the CI matrix (`.github/workflows/tests.yml`), which also runs weekly to catch Forge URL rot.
